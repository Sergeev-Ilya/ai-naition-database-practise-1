# Спорные решения

- **Телефон строго в E.164.** Спецификация отклоняет номера без `+` и кода страны, хотя бизнес-задача требует хранить телефоны без уточнения формата. Это может мешать вводу привычных локальных номеров. Подтвердить обязательность E.164 и определить, кто приводит номера к этому виду; альтернатива — принимать локальный ввод и нормализовать его по выбранной стране.
- **Поиск имени только по точному совпадению.** В контракте поиск по имени означает совпадение всей нормализованной строки, хотя задача и пользовательские сценарии не ограничивают поиск точным совпадением. Это исключает поиск по части имени/фамилии. Подтвердить точный поиск либо выбрать правила префиксного/частичного поиска.
- **Порог p99 20 мс для поиска при 100 RPS и миллионе записей.** Это конкретный SLA, которого нет в бизнес-задаче; ADR также фиксирует p99 50 мс для создания. Такие пределы влияют на архитектуру, индексирование и стоимость эксплуатации. Подтвердить нагрузочный профиль, среду измерения и необходимость обоих порогов; альтернатива — сначала задать целевой пользовательский отклик и проверять его на согласованном оборудовании.
- **Выбор PostgreSQL 18 и фиксированного стека в ADR.** Бизнес-требование просит готовое open-source решение для базы данных с UI и API, а ADR выбирает PostgreSQL плюс отдельный Spring Boot UI/API. Не подтверждено, что допустима отдельная веб-оболочка вместо готового UI базы, и не сравнивались другие подходящие open-source варианты. Подтвердить трактовку требования и ограничения по развертыванию/администрированию до фиксации стека.
