# Proposal

## Why

Согласно [бизнес-задаче](../../../business-task.md), нужен справочник имен и телефонов с визуальным интерфейсом, программным API, двусторонним поиском и надежным хранением большого объема данных. [Critical User Journeys](../../../critical-user-journeys.md) дополнительно определяют сохранение, уведомление о дубле и пользовательские процессы поиска.

## What Changes

- Добавляется создание записи «имя + телефон» с валидацией и защитой от дублей.
- Добавляется поиск телефонов по имени и имен по телефону через REST API.
- Добавляется веб-интерфейс для сохранения и поиска.
- Готовая open-source СУБД используется как хранилище; UI и REST API реализуются приложением отдельно.
- Устанавливаются подтвержденные требования: до 1 000 000 записей, 100 RPS, p99 до 20 мс для поиска и до 50 мс для создания.

## Capabilities

### New Capabilities

- `contact-records`: создание, валидация, дедупликация и надежное хранение записей.
- `contact-search`: API-поиск записей по имени или телефону.
- `contact-web-ui`: пользовательские процессы сохранения и поиска в браузере.

### Modified Capabilities

Нет.

## Impact

Затрагиваются хранилище контактов, REST API, веб-интерфейс и развертывание. Согласно [ADR-001](../../../ADR.md), UI и API поставляются одним приложением на Java 25 и Spring Boot 3.5, PostgreSQL 18 запускается отдельным сервисом, а схема управляется Flyway.
