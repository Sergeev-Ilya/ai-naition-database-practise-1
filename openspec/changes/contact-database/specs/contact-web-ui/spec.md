# Spec Delta

## Purpose

Определяет наблюдаемое поведение веб-формы сохранения и поиска контактов, включая ошибки ввода и отображение результатов.

## ADDED Requirements

### Requirement: Начальное состояние страницы
При открытии URL приложения система SHALL показать пустые поля `Имя` и `Телефон`, кнопки `Сохранить` и `Найти`, а также пустую область результата.

#### Scenario: Открытие приложения
- **WHEN** пользователь открывает URL приложения
- **THEN** форма доступна для ввода, а сообщение об ошибке и результаты отсутствуют

### Requirement: Сохранение через форму
По кнопке `Сохранить` интерфейс SHALL проверить оба поля и вызвать `POST /api/v1/contacts`. До ответа повторная отправка SHALL быть недоступна. После ответа интерфейс SHALL показать результат и снова разрешить отправку.

#### Scenario: Успешное сохранение
- **WHEN** оба поля валидны и API возвращает HTTP `201`
- **THEN** интерфейс показывает сообщение `Запись сохранена`

#### Scenario: Не заполнено поле
- **WHEN** пользователь нажимает `Сохранить`, а имя или телефон пусты
- **THEN** интерфейс не вызывает API и показывает ошибку у незаполненного поля

#### Scenario: Найден дубль
- **WHEN** API возвращает код `CONTACT_ALREADY_EXISTS`
- **THEN** интерфейс показывает `Данный телефон и имя уже зарегистрированы`

#### Scenario: Сбой сервера
- **WHEN** API недоступно или возвращает HTTP `5xx`
- **THEN** интерфейс показывает `Не удалось выполнить запрос. Повторите позже` и сохраняет введенные значения

### Requirement: Поиск через форму
По кнопке `Найти` интерфейс SHALL проверить, что заполнено ровно одно поле, вызвать `GET /api/v1/contacts` с этим критерием и показать найденные значения. Этапы: локальная проверка, запрос API, обработка ответа, обновление области результата.

#### Scenario: Поиск по имени
- **WHEN** заполнено только поле `Имя` и пользователь нажимает `Найти`
- **THEN** интерфейс вызывает API с `name` и показывает телефоны из ответа

#### Scenario: Поиск по телефону
- **WHEN** заполнено только поле `Телефон` и пользователь нажимает `Найти`
- **THEN** интерфейс вызывает API с `phone` и показывает имена из ответа

#### Scenario: Заполнены оба поля
- **WHEN** заполнены `Имя` и `Телефон` и пользователь нажимает `Найти`
- **THEN** интерфейс не вызывает API и показывает `Можно искать только по одному параметру`

#### Scenario: Оба поля пусты
- **WHEN** оба поля пусты и пользователь нажимает `Найти`
- **THEN** интерфейс не вызывает API и показывает `Заполните имя или телефон`

#### Scenario: Ничего не найдено
- **WHEN** API возвращает пустой массив `items`
- **THEN** интерфейс показывает `Ничего не найдено`

### Requirement: Производительность интерфейса
При стабильном соединении страница SHALL стать готовой к вводу не позднее 2 секунд для 95% загрузок. После ответа API результат SHALL появиться не позднее 100 мс для 99% операций.

#### Scenario: Измерение скорости интерфейса
- **WHEN** выполняется 1000 загрузок страницы и 1000 обработок успешного ответа API
- **THEN** p95 времени готовности не превышает 2 секунды, а p99 времени отображения ответа — 100 мс
